## Errors on untried actions spread

The log holds transitions: what the robot observed, what it did, the reward, what came next and whether the episode ended <Cite id="offline-rl-tutorial-2020" />. Each value estimate is built from the next, so an error on an action outside the data spreads through every estimate that depends on it <Cite id="bear-2019" />. Real-ORL, on over 6,500 trajectories from 800 robot hours, found that offline RL and imitation prefer different action spaces <Cite id="real-orl-2022" />.

## Four properties make a log usable

| Property | What it means | Evidence |
| --- | --- | --- |
| Behavior coverage | Who produced each episode | D4RL builds benchmarks from such mixtures <Cite id="d4rl-2020" /> |
| Outcome coverage | Rewards separate success, progress and failure | COG chained four skills on a completion-only reward <Cite id="cog-2020" /> |
| Clean transitions | Correct timestamps, episode ends and units | Mishandled time limits invalidate replay <Cite id="time-limits-2017" /> |
| Overlap with deployment | Same cameras and control rate | PTR learned new WidowX tasks from 10 demonstrations <Cite id="ptr-2022" /> |

Learned reward models now supply outcomes. Robometer, trained on over a million trajectories including failures, gives dense rewards for mixed-quality data <Cite id="robometer-2026" />. In RoboReward's tests, reward accuracy tracked downstream RL at a correlation of 0.83 <Cite id="roboreward-2026" />.

Also: verified bridges between recorded motions <Cite id="needlework-2026" />; see [datasets](/data-hardware/datasets) and the [robot-learning stack](/data-hardware/robot-learning-stack).

## Every method avoids trusting unsupported values

Methods differ in how they avoid unsupported values, but how a policy is extracted from them often matters more <Cite id="park-bottleneck-2024" />.

| Approach | Example | Idea and result |
| --- | --- | --- |
| Pessimism | CQL (2020) | Pushes down values of actions missing from the data <Cite id="cql-2020" /> |
| Ranking instead of pessimism | RankQ (2026) | Ranks actions so the policy is not anchored to poor data; a VLA's real cube stacking rose from 43.1% to 88.9% <Cite id="rankq-2026" /> |
| Never query unseen actions | IQL (2022) | Learns values only from actions in the data <Cite id="iql-2022" /> |
| Values over action chunks | CO-RFT (2025), Q-chunking (2025) | Learn values for short sequences of actions; CO-RFT fine-tuned a VLA from 30 to 60 demonstrations <Cite id="co-rft-2025" /> <Cite id="q-chunking-2025" /> |
| Pull toward the data | TD3+BC (2021) | Adds an imitation term to ordinary RL and matches more complex methods <Cite id="td3-bc-2021" /> |
| One-step actor | Flow Q-Learning (2025) | Trains a fast one-step policy beside an expressive one <Cite id="flow-q-learning-2025" /> |
| Scale the value function | QT-Opt (2018), Q-Transformer (2023) | QT-Opt reached 96% grasp success on unseen objects from over 580,000 real attempts <Cite id="qt-opt-2018" />; Q-Transformer predicts values one action dimension at a time <Cite id="q-transformer-2023" /> |

Even with 1,000 times the usual data, many offline algorithms saturate well below the best possible performance, and long tasks are the barrier <Cite id="horizon-reduction-2025" />.

## Clean demonstrations favor behavior cloning

For clean expert demonstrations, behavior cloning is the better default: Robomimic's cloning baseline with memory was strong on human demonstrations where offline RL struggled <Cite id="robomimic-2021" />. Kumar and colleagues favor offline RL for sparse rewards, noisy data and long tasks stitched from pieces of different trajectories <Cite id="offline-rl-vs-bc-2022" />.

<TrajectoryStitching className="my-6" />

Reliable values are what make offline RL pay. Across 240 hours of demonstrations and over 3,000 rollouts, Robo-ValueRL found they let offline RL scale better than cloning <Cite id="robo-valuerl-2026" />. In a November 2026 chess study on an SO-101 arm, RECAP-style advantage conditioning <Cite id="pistar06-2025" />, filtered cloning and residual RL gave no measurable gain over plain cloning <Cite id="chess-vla-adaptation-2026" />.

Also: per-subtask values <Cite id="seeq-2026" />; the [behavior-cloning guide](/manipulation/bc-foundations).

## The critic cannot grade itself

Checkpoints chosen for the highest predicted value mislead. Offline RL is sensitive to its settings but ranks policies reliably when the algorithm and value estimator are held fixed <Cite id="paine-hparam-2020" />. Cross-validation can tune it without online trials <Cite id="offline-rl-workflow-2021" />, with data held out by environment, object or operator, since random splits leak neighboring frames.

Simulation counts only where its link to hardware is measured, as in SIMPLER's paired real evaluations <Cite id="simpler-2024" />. SCORE keeps simulated RL within what a real-data policy would do and raised eight real dexterous tasks from 37.8% to 89.9%, against 59.5% for the best baseline <Cite id="score-2026" />.

Also: RvS, a simple conditioned baseline <Cite id="rvs-2021" />; EDAC's ensemble penalty <Cite id="edac-2021" />.

<Image id="simpler-visual-matching-2024" />

Physical trials are the final test, with protocols fixed before policy identities are known and interventions counted, as TRI did <Cite id="tri-lbm-2025" />, or on repeatable suites such as TriFinger <Cite id="trifinger-offline-2023" />.

## Offline RL is now a warm start for online learning

Pessimistic critics fine-tune poorly; Cal-QL calibrates CQL with a one-line change and led on 9 of 11 benchmarks <Cite id="cal-ql-2023" />. Naively pretrained values often add little over random initialization <Cite id="dong-q-pretrain-2026" />.

Also: offline data mixed online <Cite id="rlpd-2023" />, offline data dropped <Cite id="wsrl-2024" />, an exploration bonus from logs <Cite id="offline-empowerment-2026" />.

| On real robots | Result |
| --- | --- |
| PA-RL (2024) | OpenVLA from 40% to 70% success in 40 minutes, with Cal-QL <Cite id="pa-rl-2024" /> |
| LWD (2026) | 95% average over eight tasks on 16 two-armed robots <Cite id="lwd-2026" /> |
| Value as Memory (2026) | 32.8% over matched offline training on long tasks <Cite id="value-as-memory-2026" /> |
| Q2RL (2026) | Values from a cloned policy, then switches between cloned and RL actions <Cite id="q2rl-2026" /> |
| BORA (2026) | Updates a small residual network on a frozen VLA <Cite id="bora-2026" /> |

See [RL fine-tuning](/manipulation/rl-finetuning).

## When offline RL is worth trying

Offline RL earns its complexity when the log's actions, rewards, endings and timing are trustworthy and its behavior should not all be imitated equally. Deployment must stay within what the data covers; unseen states are often the larger barrier <Cite id="park-bottleneck-2024" />.
