Hierarchical robot architectures split deciding *what* to do from deciding *how* to move. The high level began as a skill-picking planner <Cite id="saycan-2022" /> and now runs inside the policy, as in π0.5 <Cite id="pi05-2025" />, or beside it, as in Gemini Robotics ER 2 <Cite id="gemini-robotics-2-2026" />.

## SayCan: the planner picks a skill

A language model can write a sensible plan that the robot cannot carry out <Cite id="saycan-2022" />, and zero-shot plans often fail to map to admissible actions <Cite id="huang-zero-shot-planners-2022" />. SayCan scores each skill in a library twice: the language model rates it as the next step, and a learned <Term id="affordance">affordance</Term> value estimates whether it can succeed from here. The product picks the skill, and the loop repeats until "done" wins <Cite id="saycan-2022" />.

Inner Monologue closed the loop with language feedback such as success detection <Cite id="inner-monologue-2022" />. Text2Motion checks whole skill sequences for geometric feasibility and solved 82% of long-horizon problems, against 13% for earlier language planners <Cite id="text2motion-2023" />.

## Code as Policies: the planner writes programs

Code as Policies (2022) has a language model write Python that calls supplied perception and control functions, writing missing ones recursively. It cannot check a program in advance, and on real robots many failures traced to inaccurate object detections <Cite id="code-as-policies-2022" />. VoxPoser's generated code queries a <Term id="vision-language-model">VLM</Term> for 3D maps of where the arm should and should not go <Cite id="voxposer-2023" />.

## Coding agents return

In late 2026 code-writing planners came back as coding agents that test and repair their own programs, usually with model weights fixed.

| System | What the agent does | Result |
| --- | --- | --- |
| RPG <Cite id="rpg-2026" /> | Revises a skill library and its own instructions through simulated practice | 28.6% to 95.0% on held-out starts of 22 tasks; 30 of 30 physical trials |
| SimEX <Cite id="simex-2026" /> | Builds a toolbox in simulation and corrects the simulator from real trials | Towel folding and barcode scanning from 10 minutes of real interaction |
| RAX <Cite id="rax-2026" /> | Explores online without demonstrations and compiles what worked into programs | 37.4 points over the best prior learned policy, using over \$100,000 of API credits |
| CoEvolve <Cite id="coevolve-2026" /> | Writes coordination code for two simulated Unitree G1 humanoids | 8 of 15 payload runs; four baselines finished none, under differing settings |
| Apple AMP1 <Cite id="apple-amp1-2026" /> | Commands the arm with no grasping or placing skills supplied | 85.6% zero-shot on RoboLab-120 against 49.2% for a leading VLA; 104 of 108 real trials |
| ChunkAct <Cite id="chunkact-2026" /> | Launches chains of primitives in one call | 2.9 times fewer model calls |

Also: ASENA <Cite id="asena-2026" />, EmbodiedSWE <Cite id="embodiedswe-2026" />, RoboHarn-Evo <Cite id="roboharn-evo-2026" />, AW-0 <Cite id="aw0-agentic-wam-2026" />, Ken Goldberg on agentic robotics <Cite id="goldberg-agentic-robotics-2026" />.

## Keypoints: the planner points

From 2024, vision-language models handed the controller points in the image marking where to grasp, move and place. MOKA has a VLM choose grasp, function and target points among marked candidates. Depth from the [perception pipeline](/classical/perception/) lifts them into the robot's frame, with no full 6-DoF object pose <Cite id="moka-2024" />.

<Image id="hamster-2d-paths-2025" />

RoboPoint trains a VLM to predict such points; it hit the target region in 46.77% of Where2Place's 100 real images, against 29.06% for GPT-4o. Its robot runs add depth and a [motion planner](/classical/motion-planning/) <Cite id="robopoint-2024" />. ReKep has GPT-4o write keypoint constraints that a solver turns into replanned arm motion <Cite id="rekep-2024" />.

<KeypointString className="my-6" />

HAMSTER's VLM draws a rough 2D path for the gripper, averaging a 20-point gain over OpenVLA across seven kinds of generalization <Cite id="hamster-2025" />.

Also: Gemini Robotics-ER's points and grasps <Cite id="gemini-robotics-2025" />, RT-Trajectory's motion sketches <Cite id="rt-trajectory-2023" />, RoboBrain 2.5's 3D keypoints <Cite id="robobrain-25-2026" />.

## A VLA can reason before it acts

ECoT trains a <Term id="vision-language-action-model">VLA</Term> to write a plan, the current subtask, object boxes and the gripper's position before its action tokens. Over 314 trials per approach it beat OpenVLA on the same data by 28 points on average, 64% against 30% from a new camera view. Reasoning costs time, so ECoT reuses its high-level reasoning for five steps <Cite id="ecot-2024" />.

CoT-VLA predicts a future image as a visual goal and beat the best prior VLA by 17% on real tasks <Cite id="cot-vla-2025" />. MolmoAct writes an editable trajectory trace before acting and reached 86.6% on LIBERO <Cite id="molmoact-2025" />. In Toyota Research Institute's 2026 study, conditioning actions on chain-of-thought traces did not help in simulation <Cite id="lbm-cotraining-2026" />.

Also: RT-H's language motions <Cite id="rt-h-2024" />, ACoT-VLA's reference trajectories <Cite id="acot-vla-2026" />.

## Two speeds in one system

A large VLM runs a few times a second, too slow for fingers, so many systems since 2025 pair a slow reasoning model with a fast motor model:

| System | High level | Low level |
| --- | --- | --- |
| Helix (2025) | 7B VLM at 7 to 9 Hz <Cite id="helix-2025" /> | 80M-parameter policy at 200 Hz, trained end to end |
| Helix 02 (2026) | Same split | Adds S0, 10M parameters, at 1 kHz <Cite id="helix-02-2026" /> |
| GR00T N1 (2025) | VLM at 10 Hz <Cite id="gr00t-n1-2025" /> | Action module at 120 Hz |
| Fast-in-Slow (2025) | Shares some parameters with the low level <Cite id="fast-in-slow-2025" /> | 117.7 Hz with eight-action chunks |
| GO-2 (2026) | Lower-rate System 2 writes action intents <Cite id="agibot-go2-2026" /> | Higher-rate System 1; no rates given |

<Image id="gr00t-n1-gr1-tasks-2025" />

π0.5 puts both levels in one network: it predicts a language subtask, then actions conditioned on it <Cite id="pi05-2025" />. Hi Robot's high-level VLM turns open-ended instructions and spoken corrections into simple commands for a low-level π0, rerunning each second <Cite id="hi-robot-2025" />. In π0.6-MEM the high level also updates a memory summary <Cite id="mem-2026" />.

π0.7 can condition on subgoal images from a world model <Cite id="pi07-2026" />, and VISTA's world-model planner raised the same VLA from 14% to 69% in new scenarios <Cite id="vista-2026" />.

## Orchestrators call the policy like a tool

Gemini Robotics 1.5 added the ER 1.5 orchestrator <Cite id="gemini-robotics-15-2025" />, which Google opened as a high-level model that can call a VLA or user-defined functions <Cite id="gemini-robotics-er-15-dev-2025" />. In [Gemini Robotics 2](/manipulation/generalist-policies/), ER 2 coordinates with the VLA over multi-minute tasks <Cite id="gemini-robotics-2-2026" /> and scores 57.4% on progress classification <Cite id="gemini-robotics-er-2-2026" />. With Gemini Robotics 2.5, ER tracked a kitting workflow while the VLA moved Apollo 2's hands, at 96% success on Mercedes-Benz lines <Cite id="gemini-robotics-2-5-2026" />.

NVIDIA's GR00T 2 uses a reasoning agent that calls the world action model as a tool and repairs dropped parts with code skills. With it, a YAM arm completed 97 or 98 of 100 assemblies of each of three toys, against 71 to 84 for the policy alone <Cite id="gr00t-2-2026" />.

Robo-COP fine-tunes the VLA under an orchestrator during deployment, keeping an update only if it improves the skills it targeted. Success on three real tasks rose from 38.3% to 50.0% <Cite id="robo-cop-2026" />.

## Neither design has won

[Both designs persist](/frontier/competing-theses/). On a real ALOHA robot, the best hierarchy placed 12 of 15 fruits, against 9 for a naive hierarchy and 3 for a flat VLA <Cite id="orchestrating-policies-2026" />. Hierarchy inside a network can stall: token-by-token waypoint planning took 57 VLM forward passes until the authors cut latency 8.7-fold <Cite id="fast-plans-2026" />.
