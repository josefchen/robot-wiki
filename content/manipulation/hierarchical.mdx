Hierarchical robot architectures decouple the *what* (decisions about tasks or subtasks) from the *how* (low-level motor control). Historically, hierarchical approaches in robotics have involved a planner that selects skills <Cite id="saycan-2022" />. More recently, the high level is either integrated into the policy, as in π0.5 <Cite id="pi05-2025" />, or kept separate, as in Gemini Robotics ER 2 <Cite id="gemini-robotics-2-2026" />.

## SayCan: the planner picks a skill

A language model can generate reasonable-sounding but unrealizable plans <Cite id="saycan-2022" />, and zero-shot generated plans often fail to map to admissible robot actions <Cite id="huang-zero-shot-planners-2022" />. SayCan scores each skill in a library twice: the language model rates it as the next step, and a learned <Term id="affordance">affordance</Term> value estimates whether it can succeed from here. The product picks the skill, and the loop repeats until "done" wins <Cite id="saycan-2022" />.

Inner Monologue closes the loop by feeding the language model with language feedback, such as success detection <Cite id="inner-monologue-2022" />. Text2Motion validates entire sequences of skills for their geometric feasibility and achieves a success rate of 82% in long-horizon manipulation problems, whereas earlier language planners achieved 13% <Cite id="text2motion-2023" />.

## Code as Policies: the planner writes programs

In Code as Policies (2022), a language model outputs Python code which uses provided perception and control functions, writing any missing functions recursively, without the ability to test the correctness of the program ahead of time. In deployment on real robots, many task failures were attributed to inaccurate object detections <Cite id="code-as-policies-2022" />. In VoxPoser, the planner likewise generates code, which queries a <Term id="vision-language-model">VLM</Term> to generate 3D maps of permissible and non-permissible locations for the robot arm <Cite id="voxposer-2023" />.

## Coding agents return

In late 2026, planners that write code became agents that test and repair their programs.

| System | What the agent does | Result |
| --- | --- | --- |
| RPG <Cite id="rpg-2026" /> | Revises a skill library and its own instructions through simulated practice | 28.6% to 95.0% on held-out starts of 22 tasks; 30 of 30 physical trials |
| RAX <Cite id="rax-2026" /> | Explores online without demonstrations and compiles what worked into programs | 37.4 points over the best prior learned policy, using over \$100,000 of API credits |
| Apple AMP1 <Cite id="apple-amp1-2026" /> | Lets a generalist model command the arm with no grasping or placing skills | Gemini 4 Argon: 85.6% zero-shot on RoboLab-120, top VLA 49.2%; Claude Opus 5.5: 104 of 108 real trials |

Also: SimEX <Cite id="simex-2026" />, CoEvolve <Cite id="coevolve-2026" />, ChunkAct <Cite id="chunkact-2026" />, ASENA <Cite id="asena-2026" />, EmbodiedSWE <Cite id="embodiedswe-2026" />, RoboHarn-Evo <Cite id="roboharn-evo-2026" />, AW-0 <Cite id="aw0-agentic-wam-2026" />, Ken Goldberg on agentic robotics <Cite id="goldberg-agentic-robotics-2026" />.

A planner can stop a subtask before the robot has finished it. In the RoboARCade simulator, planners using GPT-6 Astra and Claude Opus 5 wrongly declared success on 24% and 39% of attempted subtasks, respectively, both using the same vision-based interface for controlling a gripper <Cite id="roboarcade-completion-2026" />.

## Keypoints: the planner points

From 2024, vision-language models handed the controller points in the image marking where to grasp, move and place. MOKA asks the VLM to select grasp, function and target points from a set of marked points in the image, and converts them into the robot's coordinate frame using depth from its [perception pipeline](/classical/perception/), without estimating full 6-DoF object pose <Cite id="moka-2024" />.

<Image id="hamster-2d-paths-2025" />

RoboPoint trains a VLM to predict such points, outperforming GPT-4o: 46.77% against 29.06% success on selecting a point within the target region on 100 real images from Where2Place. When deployed on a robot, depth information and a [motion planner](/classical/motion-planning/) are leveraged <Cite id="robopoint-2024" />. ReKep uses GPT-4o to generate keypoint-based constraints that a solver converts into revised robot arm trajectories <Cite id="rekep-2024" />.

In HAMSTER, a VLM predicts a coarse 2D path for the gripper, improving performance by 20 points on average compared to OpenVLA across seven kinds of generalization <Cite id="hamster-2025" />.

Also: Gemini Robotics-ER's points and grasps <Cite id="gemini-robotics-2025" />, RT-Trajectory's motion sketches <Cite id="rt-trajectory-2023" />, RoboBrain 2.5's 3D keypoints <Cite id="robobrain-25-2026" />.

## A VLA can reason before it acts

ECoT trains a <Term id="vision-language-action-model">VLA</Term> to first predict the plan, the current subtask, boxes for objects, and the gripper's position, before its action tokens. Over 314 trials per approach, ECoT outperforms OpenVLA trained with the same data by 28 points on average (64% against 30% success when the camera is moved to a new viewpoint). To reduce the latency introduced by reasoning, ECoT reuses the high-level reasoning for five steps <Cite id="ecot-2024" />.

CoT-VLA uses an imagined future image as an visual goal and outperforms the strongest previously proposed VLA by 17% on physical robot tasks <Cite id="cot-vla-2025" />. MolmoAct predicts an editable trajectory trace before acting, reaching an 86.6% success rate on LIBERO <Cite id="molmoact-2025" />. A 2026 study from Toyota Research Institute finds that in its simulation environment, conditioning actions on chain-of-thought style intermediate reasoning does not improve performance <Cite id="lbm-cotraining-2026" />.

Also: RT-H's language motions <Cite id="rt-h-2024" />, ACoT-VLA's reference trajectories <Cite id="acot-vla-2026" />.

## Two speeds in one system

To cope with the slow computation speed of large VLMs (a few times a second, too slow for fingers), a common practice since 2025 is to pair a slow reasoning model with a fast motor model:

| System | High level | Low level |
| --- | --- | --- |
| Helix (2025) | 7B VLM at 7 to 9 Hz <Cite id="helix-2025" /> | 80M-parameter policy at 200 Hz, trained end to end |
| Helix 02 (2026) | Same split | Adds S0, 10M parameters, at 1 kHz <Cite id="helix-02-2026" /> |
| GR00T N1 (2025) | VLM at 10 Hz <Cite id="gr00t-n1-2025" /> | Action module at 120 Hz |
| Fast-in-Slow (2025) | Shares some parameters with the low level <Cite id="fast-in-slow-2025" /> | 117.7 Hz with eight-action chunks |
| GO-2 (2026) | Lower-rate System 2 writes action intents <Cite id="agibot-go2-2026" /> | Higher-rate System 1; no rates given |

<Image id="gr00t-n1-gr1-tasks-2025" />

π0.5 integrates both levels into a single network, first predicting a language subtask and then predicting actions conditioned on it <Cite id="pi05-2025" />. Hi Robot uses a high-level VLM to translate open-ended instructions and spoken corrections into simple commands that condition a low-level π0, with the high-level VLM re-running at 1 Hz <Cite id="hi-robot-2025" />. In π0.6-MEM the high level additionally generates an updated memory summary <Cite id="mem-2026" />.

π0.7 can condition on subgoal images generated by a world model <Cite id="pi07-2026" />. Planning with a world model (VISTA) improved the performance of the same VLA in novel scenarios from 14% to 69% <Cite id="vista-2026" />.

## Orchestrators call the policy like a tool

Gemini Robotics 1.5 introduced an ER 1.5 model that serves as an orchestrator <Cite id="gemini-robotics-15-2025" />. In the Gemini Robotics developer release, Gemini Robotics ER can be used as an orchestrator for a VLA policy or other developer-defined functions <Cite id="gemini-robotics-er-15-dev-2025" />. In [Gemini Robotics 2](/manipulation/generalist-policies/), ER 2 is used in concert with the VLA for tasks spanning several minutes <Cite id="gemini-robotics-2-2026" />, and achieves 57.4% on progress classification <Cite id="gemini-robotics-er-2-2026" />. Gemini Robotics ER has also been used to monitor the progress of a kitting task while Gemini Robotics 2.5 controls the hands of Apollo 2, achieving a 96% success rate in a proof of concept with Mercedes-Benz <Cite id="gemini-robotics-2-5-2026" />.

NVIDIA's GR00T 2 uses a reasoning agent to direct GR00T's world action model, calling it as a tool, and repairs dropped parts with code skills. In this setup, a YAM robot arm completed 97 or 98 of 100 assemblies of each of three toys, compared to 71 to 84 when using GR00T's policy directly <Cite id="gr00t-2-2026" />.

Robo-COP uses an orchestrator to fine-tune the VLA during deployment, only accepting policy updates if the updated VLA performs better on the skills that Robo-COP targets, increasing success on three real-world tasks from 38.3% to 50.0% <Cite id="robo-cop-2026" />.

## Neither design has won

On a real ALOHA robot, the best hierarchy placed 12 out of 15 fruits, in contrast to 9 for a naive hierarchy and 3 for a flat VLA <Cite id="orchestrating-policies-2026" />. Hierarchies implemented within a single network can suffer from slow inference: planning waypoints token by token required 57 VLM forward passes until the authors cut latency 8.7-fold <Cite id="fast-plans-2026" />.

When given a stronger harness or trained policy to perform its motions, GPT-6 Astra does better in simulation:
