ROS 2, the Robot Operating System's second generation, is free modular robot software rebuilt for production use <Cite id="ros2-science-robotics-2022" />. For a learned policy it is the runtime that carries sensor data in and actions out.

## A policy reaches the robot only through typed messages

A policy never touches the camera or the motors: it reads typed messages and publishes commands. A `geometry_msgs/PoseStamped` carries the timestamp and frame a bare array lacks, in REP 103's SI units <Cite id="rep-103-2010" />. Nodes talk through topics for streams, services for short calls, and actions for long goals with feedback and cancellation <Cite id="ros2-interfaces-2026" />.

## QoS decides which messages reach the policy

Quality of Service (QoS) settings, inherited from DDS <Cite id="ros2-dds-design-2014" />, can make a deep reliable queue serve stale images. The default keeps 10 messages reliably; the sensor-data profile uses best effort and a smaller queue. Lifespan silently drops old messages, and endpoints with incompatible policies never connect <Cite id="ros2-qos-2026" />.

ROS 2 can add 50% latency over raw DDS <Cite id="ros2-latency-2021" />. Since Kilted Kaiju (May 2025), Zenoh's `rmw_zenoh_cpp` is Tier 1 <Cite id="ros2-kilted-2025" />.

## Every input needs two timestamps

Streams arrive at different rates, so log each reading's capture and arrival times. MCAP stores a publish time and a log time per message <Cite id="mcap-spec-2026" />, and ros2_tracing splits latency by stage for 0.0033 ms per message <Cite id="ros2-tracing-2022" />. With `use_sim_time` set, ROS time follows `/clock`, so nodes that mix it with wall time see spurious timeouts <Cite id="ros2-clock-design" />.

## tf2 knows where every frame was, and when

tf2 keeps a time-buffered tree of frames and transforms data between any two at any moment <Cite id="tf2-docs-2026" />, after Foote's tf <Cite id="tf-library-2013" />. In the tf2 tutorial, a lookup at an image's timestamp waits 50 ms before it fails <Cite id="tf2-time-tutorial-2026" />.

REP 105 defines `odom` as a drifting frame and lets `map` poses jump <Cite id="rep-105-2010" />; camera optical frames take an `_optical` suffix and their own axes <Cite id="rep-103-2010" />. A policy trained on <Term id="end-effector">end-effector</Term> motions in the base frame cannot take tool-frame motions <Cite id="modern-robotics-2017" />.

## URDF and MoveIt give the policy a robot model

URDF, the most common robot-description format, lists links, joints, geometry and limits <Cite id="urdf-dataset-2023" />. MoveIt 2's planning scene adds world geometry for kinematics and collision checks <Cite id="moveit-planning-scene-2026" />.

## rosbag2 is the experiment record

rosbag2 records timestamped messages, in MCAP by default since Iron Irwini <Cite id="ros2-iron-mcap-2023" />, and since Kilted replays them in publication order <Cite id="ros2-kilted-2025" />. Training pipelines convert bags to episode formats such as RLDS <Cite id="rlds-2021" />.

## Inference stays out of the hard real-time loop

Run inference outside the hard real-time loop unless its worst case fits, and keep page faults, dynamic allocation and blocking locks out of that loop <Cite id="ros2-realtime-docs-2026" />.

| Part | ROS 2 piece |
| --- | --- |
| Controller bridge | ros2_control <Cite id="ros2-control-docs-2026" /> |
| Supervisor | Managed nodes, which change state only on request or error <Cite id="ros2-lifecycle-design-2015" /> |
| Executor | Lyrical's EventsCBGExecutor: less CPU overhead, an unbounded event queue <Cite id="ros2-executors-2026" /> |
| GPU messages | `rosidl::Buffer` keeps byte arrays in GPU memory <Cite id="ros2-buffer-backends-2026" />, since host round trips cost latency and bandwidth <Cite id="isaac-ros-rosidl-buffer-2026" />; NVIDIA deprecated NITROS for it on 21 September 2026 <Cite id="isaac-ros-nitros-2026" /> |

## Navigation uses the same architecture

Nav2 coordinates planner, controller and recovery servers with a behavior tree <Cite id="nav2-2020" />. Its costmap takes plugins for AI outputs <Cite id="nav2-costmap-2d-2026" />, so a learned local controller can reuse a classical one's costmap, goals and fallback. Also: the Smac Planner's motion-constrained search <Cite id="smac-planner-2024" />.

## Run one ROS version and one middleware

DDS implementations interoperate only in limited cases, so run one ROS version and one middleware <Cite id="ros2-middleware-vendors-2026" />. `rmw_zenoh` nodes find each other only through a running Zenoh router <Cite id="rmw-zenoh-readme-2026" />. Nodes are not guaranteed to talk across releases, which alternate yearly between five-year long-term-support versions and shorter ones <Cite id="rep-2000-2026" />.
